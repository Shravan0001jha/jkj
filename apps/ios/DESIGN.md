# Iris Workplace for iPhone — design note

The owner runs Iris through AI employees. Away from the Mac he needs to see who is working on what,
answer what needs him, and talk to any employee. This app is that page on his iPhone. It is a thin,
native client over the Workplace API (`docs/LLD-workplace.md` §14, `packages/shared/src/workplace-api.ts`);
it holds no data of its own beyond the server URL, the bearer token and a short alert history.

Target: iOS 17+, SwiftUI, one app target, one unit-test target. Generated by XcodeGen from
`project.yml` (the same way `~/claude-dev-mobile/mobile/ios` is built), signed by team `M9YV87TCT9`,
bundle id `com.irisforu.workplace`.

## Screens and navigation

A tab bar with five tabs; Settings opens from the Office toolbar (gear) and from the connection banner.

| Tab | Shows | Actions |
|---|---|---|
| **Office** | header: needs-you count, spend today vs the ₹1000 cap (meter + number), requirement coverage (owned / planned / built / verified / released of total), lint errors when > 0; then one section per unit with an employee card each | pull to refresh; tap a card → Employee page (Talk + charter + status) |
| **Inbox** | open items first (kind pill, title, raised by, age), answered below; item detail shows the body, the structured context (action, subject, diff, links) and one button per option | tap an option → answers in place. `danger` options confirm first. `needsNote` options ask for a note. Answered items show the answer and `via` |
| **Talk** | employee picker (grouped by unit, with state), then the conversation: the session log streamed over the socket, the composer, an interrupt button while running, and an inline approval card when the session is waiting on a tool | send → `POST /employees/:id/talk`; approve/deny/always → `agent.approve`; interrupt → `POST /agents/:id/interrupt`; permission mode → `agent.mode`; charter/status/handoff in a sheet |
| **Features** | the board grouped by state, and a pivot (segmented: charter / platform / team) as a scrollable grid | tap a feature → detail: spec, requirements, assignments with their evidence (tests, commits, live-verified, not-verified, notes) and the route (why each charter) |
| **Alerts** | the in-session history of socket `alert` events (level, title, body, time); tapping one with an `inboxId` opens that Inbox item | clear |

Every employee card and Inbox row encodes its state by **shape and colour**, never colour alone:
working = filled circle with a play glyph, idle = hollow circle, blocked = octagon, needs-you =
filled circle with an exclamation, paused = pause glyph. Inbox kinds carry a glyph as well as a tint.
Every colour is a system colour so dark mode and Increase Contrast come free; every text uses
Dynamic Type styles.

Navigation: `TabView` with a `NavigationStack` per tab. Cross-tab jumps (alert → inbox item, card →
Talk with that employee) go through a small `Router` observable that the tabs read.

## Networking

- **REST**: `RestClient` over `URLSession`. Paths come from `API.swift`, a one-to-one port of
  `WORKPLACE_API` (so the app never guesses a path). Every request carries
  `Authorization: Bearer <token>`. Errors decode the contract's `{ error }` and surface as
  `WorkplaceError.server(status, message)`; 401 flips the connection state to `unauthorized`.
- **Socket**: `SocketClient` over `URLSessionWebSocketTask` at `/ws?token=…`. Reconnects with
  exponential backoff (1 s → 30 s, jittered), pings every 20 s, reconnects on foreground. Events
  decode into `ServerEvent` by the `type` discriminator; unknown types are kept as `.unknown` so an
  announced addition never breaks the client. Commands (`agent.approve`, `agent.mode`,
  `inbox.answer`) encode from `ClientCommand`.
- **Transport is injectable**: `RestClient` takes a `URLSession` (tests use a `URLProtocol` stub);
  `SocketClient` takes a `SocketTransport` protocol (tests use a fake that scripts frames).

## Models

`Contract.swift` mirrors `types.ts`, `protocol.ts`, `workplace.ts` and `workplace-api.ts` field for
field, with the same names, optionality and string unions (as `String` enums). Times stay ISO-8601
strings, parsed for display. `Record<string, unknown>` is `JSONValue`.

Drift protection, two layers:
1. `IrisWorkplaceTests/Fixtures/*.json` are shaped from the contract types and every response type
   must decode from its fixture and re-encode without loss.
2. `scripts/check-contract.mjs` reads the TypeScript unions and interfaces and compares them with the
   Swift enums and struct fields; `make test` runs it before XCTest, so a renamed field fails the run.

## State

One `@Observable` `AppModel` on the main actor owns: `Connection` (unpaired / connecting / online /
offline(reason) / unauthorized), the `RestClient` and `SocketClient`, and one store per screen
(`OfficeStore`, `InboxStore`, `TalkStore`, `FeaturesStore`, `AlertsStore`). Stores are plain
observables that expose `load()` and apply socket events through `handle(_ event:)`, so the same code
path serves the first load, pull-to-refresh and live updates, and each store is unit-tested by feeding
it events without a network.

- Office: `office.updated` replaces one card; `spend.updated` replaces the spend summary;
  `inbox.updated` recomputes needs-you.
- Inbox: `inbox.updated` upserts; an answer is optimistic only after the `POST` succeeds (act, then ack).
- Talk: `agent.updated` for the current session updates status, approval and mode; `agent.log` appends
  entries whose `agentId` matches; the history comes from `GET /agents/:id/log` when the session is
  chosen.
- Features: `work.updated` upserts a feature or an assignment of the open feature.
- Alerts: `alert` appends; if the app is not active, a local notification is scheduled
  (`UNUserNotificationCenter`, trigger nil). This only works while iOS keeps the socket alive in the
  background (seconds to a few minutes). Real reach when the app is closed needs APNs — a follow-up.

## Auth and pairing

The token lives in the Keychain (`kSecClassGenericPassword`, service `com.irisforu.workplace`,
`AfterFirstUnlockThisDeviceOnly`); the server URL lives in `UserDefaults`. First run shows Pairing:
server URL + one-time code → `POST /api/pair/exchange { code }` → `{ token }` → Keychain → `GET
/api/health` to confirm. Settings shows the URL, the connection state, the server version and data
dir from `/api/health`, and **Re-pair** (deletes the token, returns to Pairing). The token is never
displayed.

Debug builds accept `WORKPLACE_URL` and `WORKPLACE_TOKEN` launch environment variables so the
simulator and device runs can be scripted against the mock server (`mock/server.mjs`).

## App Transport Security

The server is plain HTTP on the LAN or the tailnet. `NSAllowsLocalNetworking = true` only; no
arbitrary loads. Private LAN addresses (192.168/16, 10/8, 172.16/12) and `.local` names are covered.
Tailscale's 100.64/10 addresses and `*.ts.net` names are not "local" to ATS: when Tailscale arrives,
either serve the Workplace over `tailscale serve` (HTTPS with a real certificate, no ATS change) or
add one `NSExceptionDomains` entry for the tailnet domain. Decided when the tailnet exists.

## Offline and error states

- No token → Pairing screen. 401 → "This phone is no longer paired" with Re-pair.
- Socket down → a slim banner under the navigation bar ("Reconnecting…" with the next retry time);
  the screens stay usable on their last data and REST still works when the network does.
- REST failure on load → an inline error with Retry; the previous data is kept.
- REST failure on an action (answer, send, approve) → an alert with the server's message; nothing is
  marked done locally until the server confirmed.
- Empty states say what would fill them ("No open items. Approvals, decisions and questions from the
  employees arrive here.").

## Not in this build

- APNs push (alerts only reach the phone while the app is open or recently backgrounded).
- Tailscale (the app is tested on the LAN; the ATS decision above is recorded).
- Org, Assign, Releases and Spend screens beyond what Office and Inbox show: releases, org changes and
  cap requests are approved from the Inbox, which is what the phone is for.

## Public relay sign-in (added 27 Sep, evening)

The Workplace becomes reachable from anywhere through an authenticated relay at
`https://work.irisforu.com` (deployment pending its security review). The API shapes do not change;
only how the app gets a credential and what "offline" means.

- **Modes.** `ServerConfig.mode` is `relay` (default, base `https://work.irisforu.com`) or `lan`
  (the pairing flow above, kept as a developer option behind a toggle in Settings and in the
  sign-in screen's footer). Each mode keeps its own credential in its own Keychain item
  (`relay-session`, `api-token`), so switching modes never leaks or loses the other's.
- **Sign-in.** `ASWebAuthenticationSession` on `<base>/login?app=1` (passkey, or email + Telegram
  code); first-time passkey enrolment on `<base>/login/enrol?app=1`. The page ends with a redirect to
  `irisworkplace://auth#token=<session>`; the token is read from the **fragment** only
  (`AuthCallback.parse`), never from the query, so it does not appear in any server log. The scheme
  is registered in Info.plist and `.onOpenURL` is a fallback for a redirect that lands outside the
  auth session. The session then travels as `Authorization: Bearer` on `/api` and `?token=` on `/ws`
  exactly like the LAN token. `WebAuth` is a protocol; tests inject a fake that returns a callback URL.
- **Expiry.** Sessions expire after 12 h idle or 7 d. Any 401 sets `Connection.unauthorized`; in relay
  mode the screen says "Sign in again" and re-runs the web auth; in LAN mode it offers Re-pair.
- **Mac offline.** When the Mac's tunnel to the relay is down, the relay answers 502/503/504 (JSON
  `{ error }` or an HTML page mentioning "offline"). `RestClient` maps that to
  `WorkplaceError.macOffline`, distinct from `.transport` (no network) and `.server`. The app shows
  "Your Mac is offline — Workplace unavailable" (full screen when there is no data yet, otherwise
  the strip under the navigation bar) and re-probes `/api/health` every 15 s until the Mac is back,
  then connects the socket and reloads.
- **Debug hooks.** `WORKPLACE_RELAY_URL` points relay mode at a local mock; `WORKPLACE_URL` +
  `WORKPLACE_TOKEN` still select LAN mode for scripted runs. `mock/server.mjs` serves `/login?app=1`
  and `/login/enrol?app=1` as a page whose button redirects to the callback, and `--mac-offline`
  makes it answer like a relay whose Mac is down.

## The 28–29 Sep screens (for the Android agent: same shapes, same words)

Tabs: **Office · Inbox · Talk · Room · Features**. Alerts, Spend, Releases, Settings and New request
are sheets reached from the Office toolbar (bell, `+`, `…`).

- **Office** header: four counts (need you / working / blocked / stalled, each glyph + colour), the
  spend meter (real money against the cap; "Subscription: N turns, free" beside it), coverage.
  Cards show the state reason under the state ("Paused — daily budget reached …") and a
  "Stalled since …" line on the current work.
- **Talk** opens on the Chief of Staff by default; "Someone else" (top-left) shows the picker. The
  employee page starts with a collapsible **Needs you** box: each open item that concerns this
  employee, what approve and deny do, and its option buttons (same `AnswerOptions` as the Inbox,
  same confirm/note/device-owner rules). Assistant lines are one line; tap or chevron expands.
- **Inbox item**: summary line + Details expander (D16), then *Who and what* (raised by, affects,
  if you approve / if you refuse), Links (a `#/room/<id>` link opens the thread), Context, then the
  options. Org-change items add "Read the change as a diff" → proposal view (reason, unified diff
  coloured by line, lint of the result, before→after delta, the same options).
- **Room**: thread rows = title, `headline` (one line), then "who · N msg · when · N for you ·
  charters". Thread view: header with escalation pills, one-line messages (owner's tinted and
  marked "You"; `@name` in accent), tap expands, composer with live mention pills.
- **Features**: segments Requests / Board / Pivot. Requests = newest first, each with the
  `RequestStatus` stage glyph, `line`, and one pill per assignment. Board groups by state. Pivot
  cells are tappable → the items behind the cell with evidence pills (tests, commits, live, not
  verified) and a link to the assignee's page. Feature detail has "Where it stands" and Assign.
- **New request** (`+`): one text box, optional platforms, "Send to Asha"; the sheet then shows the
  status line, which keeps updating.
- **Releases** sheet: per shippable, unreleased commits, the open release (Proposed → "Approve or
  reject" opens the Inbox item; Approved → Run, device-owner gated), the last release.
- **Spend** sheet: real money by source and basis (estimates labelled), by employee; then
  "Subscription usage (free)" with turns, tokens, list-price equivalent marked "not billed", and
  the rate-limit windows as bars.
- **Connection states**, in order of precedence: no credential → Sign in; 401 → "Your session has
  ended / Sign in again"; 503 "switched off" → "Access is switched off"; 503 "Mac offline" / WS
  1013 → "Your Mac is offline"; network → orange strip "Connection lost · retrying …"; DNS →
  "Can't reach work.irisforu.com — check your connection". Data on screen stays; nothing spins
  forever.
- **Push** (app side): register on token/sign-in/foreground; categories WP_INBOX (OPEN, DECIDE),
  WP_ROOM, WP_ALERT; `link` routes like `irisworkplace://…`; DECIDE lands on the options; dangerous
  options and approval/release/org-change/cap answers need device-owner auth first.
